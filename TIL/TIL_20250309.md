# On 20250309 I learned...
1. 로그인 기능 완료 후 feature 브랜치 > develop 브랜치에 merge 완료
    - squash merge 하려 했는데 conflict 등의 이슈로 feature 브랜치의 커밋 내역을 하나로 rebase한 후에 develop으로 rebase, merge함
2. `@LoggedIn` 어노테이션 개발 완료
    - 컨트롤러 메서드의 파라미터로 `@LoggedIn UserTokenInfo userTokenInfo` 사용 시 로그인 사용자의 정보를 받아올 수 있음
    - 유저 정보 받아와야 하는 부분에 해당 어노테이션 적용 완료
3. request DTO에서 반복적으로 userId를 세팅하는 부분 인터페이스화
   - `UserAssignRequest` 인터페이스를 각 request DTO에서 상속받아 `assignUserId` 메서드 구현
   - 컨트롤러 메서드에서 제네릭 형태로 request DTO를 받아 해당 DTO의 메서드를 실행시켜 줌
   - 이렇게 하면 각 request DTO에서 반복되는 userId 할당 작업을 공통 메서드로 사용할 수 있음
4. QueryDSL에서 `DATE_FORMAT` 함수 제거
   - `DATE_FORMAT`은 데이터베이스에 종속적인 함수이므로 사용을 지양하는 게 좋음
   - 실제로 MySQL을 사용하다가 h2로 테스트하니 해당 함수 부분에서 오류 발생
   - 해당 함수 모두 제거 후 대체 로직으로 수정함
5. Lombok `@Data` 어노테이션 제거
   - 슈퍼 어노테이션이므로 사용하는 기능만 따로 지정하기 위해 제거
