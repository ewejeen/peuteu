## 1. 공통된 코드가 반복되는 메서드를 제네릭을 사용하여 하나로 합침

### 기존
```java
public CheckDuplicateResponse checkDuplicatedEmail(String email) {
   return userJpaRepository.findByEmail(email)
         .map(user -> new CheckDuplicateResponse(false))
         .orElseGet(() -> new CheckDuplicateResponse(true));
}

public CheckDuplicateResponse checkDuplicatedNickname(String nickname) {
  return userJpaRepository.findByNickname(nickname)
         .map(user -> new CheckDuplicateResponse(false))
         .orElseGet(() -> new CheckDuplicateResponse(true));
}
```
- 이메일, 닉네임 중복 여부를 검사하는 메서드
- `map`, `orElseGet` 로직이 중복됨
- 제네릭 메서드로 공통 부분을 추출하여 중복 제거

### 변경
```java
public CheckDuplicateResponse checkDuplicate(Function<String, Optional<User>> findByField, String value) {
    return findByField.apply(value)
            .map(user -> new CheckDuplicateResponse(false))
            .orElseGet(() -> new CheckDuplicateResponse(true));
}

public CheckDuplicateResponse checkDuplicatedEmail(String email) {
    return checkDuplicate(userJpaRepository::findByEmail, email);
}

public CheckDuplicateResponse checkDuplicatedNickname(String nickname) {
    return checkDuplicate(userJpaRepository::findByNickname, nickname);
}
```
- `checkDuplicate`
  - `Function<String, Optional<User>>` 타입을 받아서 중복 여부를 체크하는 공통 메서드
  - `findByField.apply(value)`를 호출하여 Optional<User> 반환
  - 존재하면 false, 없으면 true 반환
- 이후 기존의 각 메서드에서 함수와 중복확인 필드를 인자로 전달하면 됨 
- ✅ 중복을 제거하고 확장성이 증가되었음

## 2. 로그인이 필요하지 않은 API Whitelist를 효율적으로 관리
### 기존
- 백엔드의 시큐리티 설정과 로그인 필터, 프론트엔드의 인터셉터에 똑같은 로그인 whitelist가 다 따로 하드코딩되어 있었음
- 백엔드에서 공통 설정을 한 뒤 whitelist를 받아오는 API를 만들고, 프론트에서는 이 API를 호출해 Vuex에 저장해 두고 사용하도록 수정

### 내가 원한 방향
- 백엔드: whitelist API의 경우 컨트롤러 메서드에 어노테이션을 붙여서 관리
- 프론트엔드: 해당 어노테이션이 붙은 백엔드 API 목록을 백엔드에서 받아와 whitelist 처리

### 구현
- 백엔드
  - `@NoAuthRequired` 어노테이션이 붙은 컨트롤러 메서는 로그인 없이 접근 가능
  - 해당 어노테이션이 붙은 URL 목록을 `List`로 받아올 메서드 정의함 (`FindNoAuthRequiredUrlService > getNoAuthRequiredUrls()`)
  - `SecurityConfig`에서 기존의 `permitAll` 대상 URL이 하드코딩되어 있던 부분을 `getNoAuthRequiredUrls()`의 결과를 받아오는 것으로 교체
  - `JwtAuthenticationFilter`에서 기존의 로그인 여부 확인 제외 URL이 하드코딩되어 있던 부분을 `getNoAuthRequiredUrls()`의 결과를 받아오는 것으로 교체
  - 프론트에도 정보를 제공하기 위해 API 생성 (`GET /no-auth-requires-urls`)
- 프론트엔드
  - 서버 시작 시 `GET /no-auth-requires-urls`를 호출해 Vuex Store에 저장함
  - 매 API 요청 시마다 인터셉터에서 하드코딩된 URL을 확인하던 부분을 위의 store를 조회하는 것으로 수정

### 결과
- 로그인 불필요 URL이 추가될 시 `@NoAuthRequired` 어노테이션만 추가하면 자동으로 백엔드, 프론트엔드에 동시에 적용됨
