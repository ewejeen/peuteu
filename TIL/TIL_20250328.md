# On 20250328 I learned...
## 1. 특정 포트만 휴대폰에서 접근이 안 됨

### 상황
- PC에서 본 서비스를 개발하면서 휴대폰으로 화면이 어떻게 뜨는지 확인하고 싶었음
- PC에서 ipconfig로 ipv4 주소를 확인한 후 휴대폰에 해당 ip:포트(8181)로 접근 시도
- 아무리 시도해도 **접근이 되지 않았음**
- 다른 서비스는 이런 방식으로 접근이 가능했기 때문에 대체 뭐가 문젠지 알 수가 없었음

### 시도한 방법
1. 포트 방화벽 열기
   - 사용하고자 하는 포트가 8181번이었기 때문에 Windows 방화벽 설정에서 8181 포트 TCP 인바운드 규칙을 추가함
   - 해결X. 근데 생각해 보면 8080번의 다른 서비스는 별다른 설정 없이 휴대폰에서도 접근이 됐으므로 포트 방화벽 문제는 아니라고 판단.
2. Ping 날려보기
   - Ping 날리는 앱을 다운받아서 해당 url을 호출해 봄
   - 8181 포트 자체가 열려 있지 않다고 확인함
   - 8080 포트의 다른 서비스는 잘 호출됨
3. CORS 설정 변경하기
   - 아닐 거 같긴 했지만 혹시나 CORS 문제였을 수 있기에 전체 도메인에 대해 CORS 설정을 풀어 버림
   - 여전히 아무 요청도 성공하지 못했음

### 해결 과정
- 시도하다 보니.. 아예 애플리케이션 단으로 요청이 가지 않는 것을 보아 뭔가 방화벽 문제가 맞는 거 같다고 판단함
- 하지만 포트 방화벽은 아닌 것 같았음
- 1차적으로 백신 프로그램이 의심되어 백신 프로그램을 삭제해 봄 (금융권 사이트에 들어가면 자동 설치되는 백신이므로 임시적으로 삭제해 버림)
- 그러나 여전히 동작하지 않았음...

- 혹시나 Java 방화벽 문제일지 의심이 가기 시작함
  - 8080 포트 사용하는 애플리케이션은 jdk11을 사용하고 8181 애플리케이션은 jdk17을 사용하고 있었음
  - 뭔가 jdk17에 대해 방화벽이 막혀 있는 것 같은 느낌
- jdk 버전을 바꿔서 애플리케이션을 다시 실행해보니.... **된다..!!!**
- jdk17의 방화벽 설정을 확인해 보니, 개인 프로필 방화벽은 사용이 `예`, 작업이 `허용`이었는데 공용 프로필 방화벽은 사용이 `아니오`, 작업이 `허용`이었음
- **공용 프로필 방화벽을 `사용`으로 바꾸니 해결...!!!**
